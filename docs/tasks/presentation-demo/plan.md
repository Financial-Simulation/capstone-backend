## 확정 사항 (2026-10-29)

- **발표용 PPT: [`capstone-6-presentation.pptx`](capstone-6-presentation.pptx) 12장, 약 8분 (5분 단축안 있음)**. 대본: [`script.md`](script.md), 발표자 노트에도 같은 내용
  - **2차 발표 피드백(조교 메일 10/2)과 1차 멘토링 피드백에 답하는 구조로 다시 짰다** (2026-10-29): 왜 계산기가 아니라 시뮬레이터인가 / 사용 전·후 차이 / 직접 입력하는 이유 / 전체 흐름 / 신뢰성·평가 지표
  - 1 표지 → 2 받은 질문 4개 → 3 적금이 깨지는 이유 72% → 4 계산기 4,440만 원 vs 가능성 약 58% → 5 순서가 결과를 가른다 (50만 vs 30만 반대 결론) → 6 사용 전·후 → 7 기존 서비스와 차이 → 8 전체 흐름 (S1) → 9 백테스트·평가 지표 → 10 진행 상황 → 11 시연 → 12 Q&A
  - 결과 숫자는 모두 설계 보고서(노션 「설계보고서 피드백 반영」, 10/7)의 파이썬 기준 구현 결과다. ○○ 자리 표시는 없다
- 아래 1장의 16장 구성안은 발표 시간이 늘어날 때 쓰는 확장판이다
- **데모는 수준 B로 간다.** 엔진이 발표 전에 붙지 않으므로 결과 화면은 라이브 계산이 아니다
  - 라이브: 입력 검사(오류·경고), 대출 월 상환액, 프리셋 — 지금 코드로 동작
  - 결과: 파이썬 `kernel.py`로 S1을 미리 계산한 값을 예시 결과(04-E)로 보여 주고, "기준 구현으로 계산한 값"이라고 밝힌다
  - 프론트 입력 화면이 준비 안 되면 수준 C: `http/demo.http`를 위에서부터 실행
  - PPT 10번 '진행 상황' 슬라이드가 "엔진은 다음 주부터"를 먼저 말해 주므로, 시연에서 결과가 미리 계산된 값이어도 흐름이 자연스럽다
- 예시 결과(04-E)에 쓸 S1 결과는 보고서 값(가능성 약 58%, 중앙값 3,389만 원, 빚질 가능성 19%, 계산기 4,440만 원)과 같아야 한다. 프론트에 넣기 전에 조민석 님이 `kernel.py` 출력으로 한 번 더 확인

### 디자인 가이드 (Figma 톤에 맞춤)

- 배경 흰색, 본문 짙은 회색, 강조 파랑(Figma 버튼 색), 위험·현금 부족은 주황 — 04 결과 화면과 같은 색 규칙을 슬라이드에도 쓴다
- 화면 이미지는 Figma 「화면 초안」에서 내보낸다. 프론트가 완성되면 **실제 화면 캡처로 교체** (와이어프레임의 ○○ 자리가 그대로 보이면 안 됨)
- 금융 용어 대신 서비스 문구 그대로: "몬테카를로" 대신 "미래 2,000개", "분위수" 대신 "범위"

### 숫자 주의

Figma 와이어프레임의 숫자(58%, 4,440만 원, 51%~83%)는 **자리 표시용**이다. 발표 전 S1을 seed `20261007`로 실제 계산해 받은 값으로 PPT·대본을 모두 바꾼다. 슬라이드 2·3·7·13의 숫자는 한 번에 같이 바꿀 것.
