# 컨텍스트 (Context)

> 작업명: API 명세 개편
> 최종 업데이트: 2026-10-10

## 배경

- 기존 API 명세(2026-10-02)는 **기능명세서 기준**으로 작성돼 설계 보고서 5~7장(실직·급전 모델, 검증)과 연결이 안 됐다. 그대로 구현하면 "보고서의 모델이 서비스에 없다"는 지적을 받는다.
- 데이터분석 담당이 `API_명세서_수정본.pdf`로 개편안을 제안했다. 방향은 받아들이고, 검토하면서 아래를 추가로 고쳤다.

## 수정 제안서 검토 결과

### 받아들인 것
- 같은 seed로 비교 (시나리오별 캐시 재사용 폐기)
- `startMonth`를 입력에 포함 (서버 날짜 대신)
- 확률 반올림·분위수 정의 고정 (Java 이식본을 정답 파일과 대조하려면 필요)
- 기존 응답 래퍼·오류 체계·`inputMode`·`LoanCalculator` 공유 유지

### 검토하며 고친 것
- `emergencyFirstAmount`를 `adjustments`에서 입력 필드로 올림
- `adjustments` 필드 전체 목록 정의 (중첩 입력 ↔ 평평한 이름 매핑)
- 과거 `startMonth`로 이어서 하기 처리 규칙
- localStorage 스키마 버전 규칙 (`v1` → `v2`)
- `/robust` 동시 작업 상한, 단일 인스턴스 전제 명시
- `/meta`에 보고서 5.2 파라미터 20개 전부 (FR-10 "근거 없는 수치 0개")

### 수정 제안서에서 발견한 문제 (보고서 쪽 수정 필요)
- 존재하지 않는 **FR-13** 인용 (보고서는 FR-01~12). `startMonth`, `/inputs/validate`, `/examples`는 보고서에 없는 추가 사항
- 위험 원인 예시 `prolongedUnemployment: 0.0`이 보고서 3.1의 대표 경로(실업 장기화)와 모순
- S1 예시가 첫 화면부터 `WARN_MONTHLY_SHORTFALL` (여유 46.5만 원 < 저축 50만 원)
- 보고서 FR-09 "필요 월 저축액"이 사실상 의미 없음 — 저축하지 않은 돈도 모은 돈에 들어가 저축액만으로는 확률이 거의 안 움직인다
- 경고 목록이 보고서 7.2(경고 6종)보다 적음 (3종)
