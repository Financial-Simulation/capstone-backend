# 결정 노트 (Decision)

> 작업명: 계산 엔진 Java 이식
> 최종 업데이트: 2026-11-02
> 기준: `finance-simulator-reference` (kernel.py / engine.js v1.6, 구현 명세서)

## 구현 결정 사항

### Python을 호출하지 않고 Java로 이식한다
- 결정: 엔진을 `simulation/engine`에 Java로 옮기고, Python·JS는 정답을 만드는 기준으로만 쓴다.
- 이유: 구현 명세서가 이 방식을 전제로 하고, API 명세의 예시 값은 sfc32 난수로 계산한 값이라 같은 난수를 써야 맞는다. 서버 안에서 계산하므로 NFR-03(1초·3초)도 지킨다.
- 검토한 대안:
  - Python을 별도 서버(FastAPI 등)로 띄워 호출: 배포 대상이 둘이 되고, 기준 구현의 난수(PCG64)가 달라 API 예시 값과 ±1%p 어긋남 → 기각
  - Spring에서 Python 프로세스 실행: 요청마다 프로세스 비용, numpy 설치 필요 → 기각
  - JS 엔진을 JVM에서 실행(GraalJS): 의존성만 늘고 구조상 이점 없음 → 기각

### 값과 정답 파일은 저장소로 복사해 쓴다
- 결정: `params.json`은 `src/main/resources`, `golden.json`·`analysis_golden.json`은 `src/test/resources/golden`에 둔다. 클론 폴더는 `.gitignore`에 넣었다.
- 이유: 클론이 없어도 빌드·테스트가 돌아야 한다.
- 기준 구현이 바뀌면: 기준 저장소에서 다시 만든 세 파일을 복사하고 테스트를 돌린다.

### `/robust`는 메모리 작업으로 만든다
- 결정: 스레드 2개 풀 + 동시 2개 상한(`JOB4001`) + 완료 후 10분 보관. API 명세의 운영 전제와 같다.
- 이유: Redis 큐는 팀 합의 전이다 ([[infra-queue-k6-aws-cicd/decision]]). 입력은 변환 값만 작업에 넘기고 끝나면 사라진다.
- 재검토: 로컬 측정에서 작업이 1초 안에 끝났다. API 명세의 "1~2초면 동기로 바꿀지 판단" 조건에 해당하므로 팀이 정한다.

### 명세서에 없는 경우의 처리
- 미리보기에서 조정 때문에 한쪽 계획만 청년미래적금 대상이면(소득 조정 등) 대상인 쪽 값만 채우고 `diff`는 null로 둔다. 명세서는 둘 다 비대상인 경우만 정의한다.
- `requiredVariableExpenseCut.searched`는 실제 탐색 범위("50,000원~600,000원, 50,000원 간격")를 적는다. API 예시의 "월 여유자금까지" 문구와 다르다 (명세서 9.3).
- 응답에는 API 예시에 없는 개수 필드(`hits`, `count`, `medianReachMonths` 등)와 `requiredMonthlySaving.grid`, `monthlySurplus`도 들어간다. 정답 파일에 있는 항목이다.
