# 재무 시뮬레이터 데모 — 팀원용 안내

폴더: `demo.html`(데모) · `docs/`(구현 명세서) · `engine/`(JS 엔진·정답 파일 2개) · `params/`(params.json·검증 리포트) · `reference_python/`(파이썬 기준 구현)

## 바로 보기
`demo.html`을 더블클릭하면 브라우저에서 열립니다. 인터넷이 없어도 동작합니다 (글꼴만 기본 글꼴로 보임).
위쪽 "예시로 보기" 버튼 세 개가 보고서의 시나리오 S1·S2·S3입니다.

## 이 데모의 위치
- 설계 보고서의 계산 로직(6장)을 그대로 구현한 **설계 검증용 시제품**입니다. 팀 구현물이 아닙니다.
- 데모는 브라우저에서 계산하지만, 실제 서비스는 보고서 4장 설계대로 백엔드에서 계산합니다.
- 데모 숫자는 난수가 달라서 보고서와 1%p 안팎으로 다를 수 있습니다.

## 정선빈 (백엔드)
- 구현 기준은 **구현 명세서** `docs/implementation_spec.pdf`(계산 순서·수식·변수·입출력 변환·난수·분석 정의)입니다. 명세서와 코드가 다르면 코드가 정답입니다.
- `engine/engine.js`가 계산 엔진 전체입니다. 파이썬 기준 구현(`reference_python/kernel.py`)과 한 줄씩 대응합니다.
- Java로 옮긴 뒤 두 정답 파일로 대조하세요 (명세서 8장).
  - `engine/golden.json`: 엔진 대조용. 같은 난수 + 파이썬 결과, 12개 프로필 × 100경로 × 120개월. 상대오차 1e-9 이하, 플래그·첫 해지 시점 완전 일치면 통과. 자바스크립트 대조 예시: `node 엔진/test_engine.js`
  - `engine/analysis_golden.json`: 분석 대조용. 8개 입력(API 입력 형식, 원 단위)마다 /simulate·/simulate/preview·/compare·/reverse·/robust 결과를 API 응답 단위로 담았습니다. 난수(sfc32)를 명세서 4장대로 옮겼다면 확률은 정확히, 금액은 원 단위까지 같아야 합니다.
- 정답 파일을 다시 만들려면 `reference_python`에서 `python make_golden.py` (numpy 필요), `engine`에서 `node make_analysis_golden.js` (약 80초)
- 파라미터는 `params/params.json` 하나를 서버 시작 때 읽으면 됩니다 (읽기 전용).
  - `params`·`policy`·`general`: 엔진 값 (만 원·연 소수, 키 이름은 명세서 3장과 같음)
  - `meta`: GET /api/meta의 근거(등급·출처·자료 기간) / `loanDefaults`: 대출 종류별 기본값 / `eventPresets`: GET /api/events/presets / `robust`: 가능성 범위 계산용 범위와 급전 확률표
  - 값을 바꾸는 순서: `kernel.py` 수정 → `python params/build_params.py` → `node params/check_params.js` (엔진 값 일치·정답 파일 재현·근거 완비를 검사하고 `params/validation_report.md`를 다시 씀)
- 적금 이자는 상품설명서대로 입금건별 단리입니다 (매달 납입 원금 합계 × 연이율/12, 납입 직후에 한 달치). 일반 적금은 12개월마다 이자에서 15.4%를 떼고 원금에 더해 다시 넣습니다. 일반 적금 금리는 프로필의 `general_rate`(연 소수, 예: 0.045)로 바꿀 수 있고, 없으면 시장 평균 3.03%입니다.
- 대출 상환 방식은 4가지: 원리금균등(annuity), 원금균등(equal_principal), 만기일시(bullet), 이자만(interest_only, 전세자금대출용). 여러 건이면 매달 상환액을 합산합니다.
- 입력 검증 규칙은 `reference_python/validate_input.py`, 엣지 테스트는 `edge15.py` (29개 케이스)

## 이윤제 (프론트엔드)
- 화면 흐름은 보고서 3장 그대로입니다: 입력 4단계 → 결과 첫 문장 → 위험 → 무엇을 바꾸면 좋을까 → 직접 바꿔보기 → 근거.
- 지켜야 할 표시 원칙 (보고서 7.5, NFR-05)
  - 첫 문장은 금융 용어 없이 확률 하나 + 행동 하나 ("기여금" 대신 "정부 지원금")
  - 절대 확률은 범위와 함께, 계산기 결과를 나란히
  - 차이가 2%p보다 작으면 "거의 차이 없음"
  - 모든 숫자 옆에 "근거" (출처·등급)
- 대출은 "대출이 있나요?"를 먼저 묻고, 있으면 대출마다 카드(종류·남은 원금·연 이자율·남은 기간·갚는 방식)를 띄웁니다. 여러 건 추가·삭제 가능, 마지막 카드를 지우면 "없어요"로 돌아갑니다.
  - 종류를 고르면 평균 금리와 흔한 갚는 방식이 미리 채워집니다.
- "더 정확하게"에 일반 적금 금리 입력이 있습니다 (기본 3.03%, 0~10% 검증). 전세자금대출은 "이자만" 방식(원금은 보증금 반환으로 상환, 보고서 6.3)이 기본입니다.
- 입력값은 서버가 아니라 브라우저 저장소에만 저장 (보고서 4.3)
- 화면 코드는 `demo.html` 안에 모두 들어 있습니다. 디자인은 참고용이며 그대로 쓸 필요는 없습니다.

## 검증 상태
- 자바스크립트 엔진 = 파이썬 기준 구현: 같은 난수에서 12개 프로필의 모든 경로 일치 (최대 상대오차 4.5e-12, 전세대출 이자만 상환·적금 금리 직접 입력·해지 원인 우선순위·이직 반복 포함)
- 구현 명세서만 보고 따로 만든 Java 구현: 엔진 정답 12개, 분석 정답 8개 입력의 모든 항목 일치
- 파이썬 기준 구현: 해석해 오차 9.1e-13 (입금건별 단리·1년 세후 재예치 포함), 제도 규칙 12/12, 불변식 3,000명 위반 0, 엣지 입력 29/29
